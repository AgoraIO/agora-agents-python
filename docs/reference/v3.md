# v3 preview reference

This reference describes the 32 implemented operations under `Agora.v3` and `AsyncAgora.v3`. For setup, complete examples, redeploy semantics and limitations, see the [v3 workflow guide](../guides/v3-api-preview.md). This custom low-level adapter is maintained from the supplied OpenAPI and reply, not Fern-generated code; see [maintainer provenance](../guides/v3-api-preview.md#maintainer-provenance).

## Shared calling conventions

All arguments are keyword-only. **Every method below also accepts `appid=None` and `request_options=None`.** `appid` defaults to the owning client's `app_id`; supplying another value targets that project for the individual call. Empty path identifiers are rejected and path segments are URL-encoded.

Compact signatures below list every resource-specific argument. A bare name is required. `=None` means an optional query/header argument; `=OMIT` means an optional body field that is absent unless supplied. `OMIT` is documentation notation, not a value to import or pass. An explicit `None` in a body becomes JSON null, which is significant for merge patch and secret-key deletion. The response names link to the [TypedDict wire schemas](../../src/agora_agent/v3/types.py); return values are dictionaries, not Pydantic instances.

Each method is available in three forms:

```python
# Given a configured sync client and async_client:
data = client.v3.agents.get(agent_id="STORED_AGENT_ID")
raw = client.v3.agents.with_raw_response.get(agent_id="STORED_AGENT_ID")
# AsyncAgora methods use the identical arguments:
# data = await async_client.v3.agents.get(agent_id="STORED_AGENT_ID")
# raw = await async_client.v3.agents.with_raw_response.get(agent_id="STORED_AGENT_ID")
```

The raw form returns `RawResponse`: `.data` is the normal result; `.headers` is `httpx.Headers`; `.etag` is an optional string; `.status_code` is the HTTP status; `.response` is the original `httpx.Response`. Keep ETag quotes exactly as received. A GET raw response is the way to obtain `If-Match` for conditional writes.

`request_options` uses the existing transport options, including `timeout_in_seconds`, `additional_headers`, and GET `max_retries`. Write retry limits are always forced to zero. Headers added through request options follow the existing transport's precedence. PATCH requests send `application/json`, as declared by staging.

## Agents: five operations

Prefix: `/conversational-ai/v1/projects/{appid}/agents`. A stored configuration's identifier is `agent_id`; it is not a v2 running-session ID.

| Method and resource-specific signature | HTTP | Result |
|---|---|---|
| `create(agent_name, instructions=OMIT, messages=OMIT, greeting=OMIT, variables=OMIT, pipeline=OMIT, filler_words=OMIT)` | POST collection | `AgentResponse` |
| `list(limit=None, cursor=None, order=None)` | GET collection | `AgentListResponse` |
| `get(agent_id)` | GET `/{agent_id}` | `AgentResponse` |
| `update(agent_id, if_match, agent_name=OMIT, instructions=OMIT, messages=OMIT, greeting=OMIT, variables=OMIT, pipeline=OMIT, filler_words=OMIT)` | PATCH `/{agent_id}` | `AgentResponse` |
| `delete(agent_id)` | DELETE `/{agent_id}` | `AgentDeleteResponse` |

`if_match: str` is required by the SDK signature and becomes `If-Match`. Agent create has no `idempotency_key` parameter. `order` accepts `create_ts.asc` or `create_ts.desc`. Body structures are documented by `AgentCreateModel`, `AgentPatchRequest` and the contract schemas. Pipelines use `mode="cascaded"` with ASR/LLM/TTS or `mode="realtime"` with MLLM. Provider credentials use `mode="managed"` or `mode="byok", fields={"api_key": "$secrets.support.openai"}`. Field names are vendor-specific; saved agents require secret references while ephemeral agents also accept inline values.

`AgentResponse` includes `agent_id`, `agent_name`, creation/update timestamps, and configured fields. Keys, custom headers and other write-only credentials are not recoverable from GET. The low-level update sends only supplied fields; unlike AgentKit redeploy it does not construct a replacement-style patch.

## Secrets: eight operations

Prefix: `/conversational-ai/v1/projects/{appid}/secrets`. Set names and keys are distinct path components. Secret values are write-only.

| Method and resource-specific signature | HTTP | Result |
|---|---|---|
| `create(name, secrets)` | POST collection | `SecretSet` |
| `list(limit=None, cursor=None, order=None)` | GET collection | `SecretList` |
| `get(name)` | GET `/{name}` | `SecretSet` |
| `replace(name, if_match, secrets)` | PUT `/{name}` | `SecretSet` |
| `update(name, secrets, if_match=None)` | PATCH `/{name}` | `SecretSet` |
| `delete(name, if_match)` | DELETE `/{name}` | `SecretDeleted` |
| `set_key(name, key, value, if_match=None, if_none_match=None)` | PUT `/{name}/keys/{key}` | `SecretKey` |
| `delete_key(name, key, if_match=None)` | DELETE `/{name}/keys/{key}` | `SecretDeleted` |

`secrets` is a map of key names to string values for create/replace. Update also accepts null values to remove individual entries. `replace` replaces the set; `update` changes supplied entries. `value` writes a single string. Names and keys follow the staging contract's 1–64 letter/digit/underscore syntax; `secret_ref` validates those components locally.

| Argument | Header | Requirement |
|---|---|---|
| Replace/delete `if_match` | `If-Match` | Required by their SDK signatures |
| Update/delete-key `if_match` | `If-Match` | Optional in the published staging signatures |
| Set-key `if_match` | `If-Match` | Optional conditional write |
| Set-key `if_none_match` | `If-None-Match` | Optional; `"*"` expresses create-if-absent intent |

Use the condition appropriate to the write; the SDK does not resolve conflicting conditions locally. Retain server errors rather than assuming an optional signature guarantees an unconditional write is accepted. Set `order` to `create_ts.asc` or `create_ts.desc` for list.

```python
# Given client, a configured Agora instance:
client.v3.secrets.set_key(name="support", key="new_key", value="NEW_VALUE", if_none_match="*")
raw = client.v3.secrets.with_raw_response.get(name="support")
if raw.etag is None:
    raise RuntimeError("Missing secret-set ETag")
client.v3.secrets.update(name="support", if_match=raw.etag, secrets={"new_key": "ROTATED_VALUE"})
```

## Numbers: five operations

Prefix: `/conversational-ai/v1/projects/{appid}/numbers`. A number resource has `number_id` and an E.164 `number` string. Registration and stored-agent assignment are scoped to the app/project.

| Method and resource-specific signature | HTTP | Result |
|---|---|---|
| `create(number, sip_trunk, description=OMIT, inbound=OMIT)` | POST collection | `NumberResponse` |
| `list(limit=None, cursor=None, order=None)` | GET collection | `NumberListResponse` |
| `get(number_id)` | GET `/{number_id}` | `NumberResponse` |
| `update(number_id, if_match, number=OMIT, description=OMIT, sip_trunk=OMIT, inbound=OMIT)` | PATCH `/{number_id}` | `NumberResponse` |
| `delete(number_id)` | DELETE `/{number_id}` | `NumberDeleteResponse` |

Update requires `if_match: str` and sends `If-Match`. Create rejects `idempotency_key` and explicit idempotency headers. `order` accepts `create_ts.asc` or `create_ts.desc`.

`SipTrunkInput` requires `hostname`. Optional fields are `name`, `port`, `transport` (`udp`, `tcp`, `tls`), `auth` (`username`, `password`), and the currently unsupported `allowed_ips`. `InboundInput` requires `agent`, which is a stored agent ID or null, and optionally `call_policy`. Supported policy fields are `max_call_duration_seconds` and `max_silence_duration_ms`; `end_call` and `transfer` are not implemented on staging. SIP-password secret references are also unsupported there.

```python
# Given client and support, a deployed handle:
number = client.v3.numbers.create(
    number="+12025550123",
    sip_trunk={"hostname": "YOUR_APPROVED_SIP_HOST", "transport": "tls", "port": 5061},
    inbound={"agent": support.id},
)
# Store number["number_id"] for subsequent conditional updates or assignment.
```

## Sessions: six operations

Prefix: `/conversational-ai/v1/projects/{appid}/sessions`.

| Method and resource-specific signature | HTTP | Result |
|---|---|---|
| `list(channel=None, status=None, started_after=None, started_before=None, limit=None, cursor=None)` | GET collection | `SessionList` |
| `get(agent_session_id)` | GET `/{agent_session_id}` | `SessionResponse` |
| `start(agent_id, transport, values=OMIT, labels=OMIT, lifecycle=OMIT, data_policy=OMIT, idempotency_key=None)` | POST collection | `StartSessionResponse` |
| `start_ephemeral(agent, transport, values=OMIT, labels=OMIT, lifecycle=OMIT, data_policy=OMIT, idempotency_key=None)` | POST `/ephemeral` | `StartSessionResponse` |
| `update(agent_session_id, transport=OMIT, agent=OMIT)` | PATCH `/{agent_session_id}` | `SessionUpdateResponse` |
| `stop(agent_session_id)` | POST `/{agent_session_id}/stop`, no request body | empty dictionary |

Session requests follow the supplied OpenAPI plus the engineering reply corrections. `RtcSessionTransport` requires `type="rtc"`, `channel` and exactly one non-wildcard, nonzero `subscribe_uids` entry; omitting `uid` or setting agent UID `0` requests automatic assignment. Optional fields: `token`, `encryption` (`mode`, `key`, optional base64 `salt`), `audio_scenario` (`aiserver` default or `chorus`). String UIDs are agreed but may require backend rollout; agent/subscriber types must match. Low-level `SessionTransport` also accepts `TelephonyTransport`: `type="telephony"`, `from` (registered project number UUID), `to` (E.164), and optional `CallPolicy`. All six outbound policy fields are typed: ring/call/silence limits, voicemail, end-call and transfer. AgentKit session creation remains RTC-oriented; no high-level outbound-call helper is added. Stop-to-hangup/ringing behavior remains open.

`SessionLifecycle` uses integer milliseconds: idle timeout 0–3,600,000; max duration 1,000–3,600,000; optional `graceful_stop` with boolean `enabled` and timeout 0–120,000 (default 30,000). `values` maps variable names to primitive values; `labels` maps strings to strings and works for ephemeral sessions too. `DataPolicy.retention` is `30_days` (default) or `none`.

Start normalizes corrected 200/`create_ts`/uppercase and rollout 201/`created_at`/lowercase data to `agent_session_id`, `create_ts`, uppercase status. Raw HTTP status/body remain available in `.response`. Start/ephemeral accept `Idempotency-Key`; no `client_reference` parameter remains. Session PATCH updates token, messages and active LLM/MLLM params; no speculative action endpoints are exposed.

List and retrieve are project-wide reads. There is no `agent_id` filter and, more fundamentally, the published responses do not carry a reliable stored-agent association. Summaries contain `agent_session_id`, `start_ts` and `status`. Detail may include `agent_name`, `stop_ts`, `message`; the current contract has no `analysis` result field; a nonunique name does not establish ownership by a stored agent.

`status` accepts comma-separated statuses, for example `"STOPPED,FAILED"` for historical sessions; returned status values are `IDLE`, `STARTING`, `RUNNING`, `STOPPING`, `STOPPED`, `FAILED`. The SDK omits the filter when `status=None`; the published staging server default is `RUNNING`. `started_after` / `started_before` are integer timestamp filters documented as Unix seconds in the staging guide.

No extraction-result field is promised by the current session response contract. Unknown rollout fields remain readable in returned dictionaries. AgentKit analysis and outbound-call helpers are not provided.

## Pagination, errors and transport

| Resource | Server default limit | Published range | Server default order/filter |
|---|---|---|---|
| Agents | 50 | 1–200 | `create_ts.desc` |
| Secrets | 50 | 1–200 | `create_ts.desc` |
| Numbers | 50 | 1–100 | `create_ts.desc` |
| Sessions | 20 | Minimum 1; no maximum declared in OpenAPI | `status=RUNNING`; no order parameter |

Omitted arguments use backend defaults, not client-side substitutions. In particular, an unfiltered session iterator still inherits the server's running-session default; pass historical status filters explicitly.

All four resources offer `list()`, `iter_pages(**list_arguments)` and `iter_all(**list_arguments)`. `list()` returns one wire page: `{data: {count, list}, has_more, next_cursor}`. Iterators follow continuation cursors and reject missing or repeated cursors. `AsyncAgora` uses `await list(...)` and `async for` for the two iterators. These helpers are used on the normal resource, not its raw-response facade.

`PreconditionFailedError` is raised for HTTP 412 and retains `.status_code`, `.headers`, `.body`; it inherits `ApiError`. Its `latest()` GETs the current parsed resource without retrying the write. On an individual key conflict it reloads the parent secret set. Reloads preserve authentication/context headers and remove all inherited and per-request `If-Match`, `If-None-Match`, and `Idempotency-Key` headers. With `AsyncAgora`, await `.latest()`. It does not return a new ETag: use another raw GET for a conditional retry. Other non-2xx responses raise `ApiError` with response status/headers/body.

All low-level writes disable automatic retries. AgentKit number assignment is the exception only in the sense that it explicitly reloads and retries once after a 412. Agent deploy, secret writes, and failed agent/number creates are never silently repeated. GET retry options use the existing shared transport.

`V3Options(base_url=None, headers={})` configures the preview origin and headers. Origin precedence is explicit option, `AGORA_AGENTS_V3_BASE_URL`, then `https://preview.ai.agora.io`. Only HTTP(S) origins without credentials, path beyond `/`, query or fragment are accepted. Legacy regional resources retain their routing. The adapter shares HTTP clients, token authentication and timeouts.

## AgentKit surface

| Operation | Synchronous | Async client |
|---|---|---|
| Store/update a builder | `agent.save(name=None, agent_id=None)` → `SavedAgent` | `await agent.save_async(...)` → `AsyncSavedAgent` |
| Load a stored handle | `SavedAgent.get(client, agent_id)` | `await AsyncSavedAgent.get(client, agent_id)` |
| Update saved config | `saved.update(config, name=None)` | `await saved.update(config, name=None)` |
| Delete | `saved.delete()` | `await saved.delete()` |
| Assign | `saved.assign_number(number, max_call_duration_seconds=None, max_silence_duration_ms=None)` | `await saved.assign_number(...)` |
| Unassign | `saved.unassign_number(number)` | `await saved.unassign_number(number)` |
| Discover assigned numbers | `saved.list_numbers()` → `List[NumberResponse]` | `await saved.list_numbers()` |
| Add a variable | `agent.with_variable(name, definition=None, **fields)` → new `Agent` | Same synchronous local builder method |
| Build a secret reference | `secret_ref(secret_set, key)` → string subclass `SecretRef` | Same local function |

The `max_*` assignment options, save `name` / `agent_id`, and update `name` are keyword-only. `SavedAgent.update(config)` preserves the handle ID/name and requires the configuration to be bound to the same client object. Handles expose `id`, `name`, `etag`, `data` and `raw` (the `client.v3.agents` resource). `list_numbers()` scans all project number pages with `limit=100`, filters `inbound.agent` locally, and makes no detail GETs; cost is one request per page. A concurrent project change can affect results during a scan. No `list_sessions()` association helper is provided without a reliable agent identity in session responses.

`with_variable` validates names, types, extraction descriptions and 1–100 unique primitive options. Numeric choices use JSON-semantic equality (`1` and `1.0` duplicate); boolean and string choices remain distinct from numbers. `UnsupportedFieldError.fields` lists unmappable builder fields. `NumberNotFoundError` reports unsuccessful E.164 lookup; `SecretRefNotSupportedError` protects v2 session paths. See the [guide's compatibility table](../guides/v3-api-preview.md#compatibility-and-backend-limits) for strict mapping, merge-patch and staging limits.

`deploy()` / `deploy_async()` are compatibility wrappers; `DeployedAgent` / `AsyncDeployedAgent` are exact class aliases for `SavedAgent` / `AsyncSavedAgent`. Prefer the version-neutral [daily workflow](../guides/agent-workflow.md) for application code. `client.secrets`, `client.numbers` and `client.campaigns` are the same resource objects as their `client.v3` counterparts. The advanced namespace remains available for raw transport and project session reads.


### Session handles

`SavedAgent.create_session(*, channel, agent_uid=None, remote_uids=None, name=None, idle_timeout=None, max_duration=None, labels=None, values=None, idempotency_key=None, token=None, encryption=None, audio_scenario=None, graceful_stop=None, data_policy=None, geofence=None, debug=None, warn=None)` returns `AgentSession`. The async handle provides `create_session` and `create_async_session`, returning `AsyncAgentSession`. Creation is local. Start/read/stop use only the new session ID. Durations on handles are seconds; graceful-stop timeout remains explicitly milliseconds. Obsolete `client_reference` raises a clear error. `name` is local only. `.raw` exposes the session resource; `.raw_agent_management` is `None`.

## Campaigns: eight operations

`client.campaigns` and `client.v3.campaigns` are identical resources; async clients use the same arguments with `await`. Prefix: `/conversational-ai/v1/projects/{appid}/campaigns`. Every method also accepts `appid=None, request_options=None`, and has `.with_raw_response`.

| Method | HTTP | Result |
|---|---|---|
| `create(name, agent_id, transport, contacts, schedule, lifecycle=OMIT, pacing=OMIT, data_policy=OMIT, idempotency_key=None)` | POST collection | `CampaignResponse` |
| `list(status=None, limit=None, cursor=None, order=None)` | GET collection | `CampaignListResponse` |
| `get(campaign_id)` | GET `/{campaign_id}` | `CampaignResponse` |
| `update(campaign_id, if_match, lifecycle=OMIT, pacing=OMIT, schedule=OMIT, transport=OMIT)` | PATCH `/{campaign_id}` | `CampaignResponse` |
| `delete(campaign_id)` | DELETE `/{campaign_id}` | `CampaignDeleteResponse` |
| `pause(campaign_id, idempotency_key=None)` | POST `/{campaign_id}:pause`, no body | `CampaignResponse` |
| `resume(campaign_id, idempotency_key=None)` | POST `/{campaign_id}:resume`, no body | `CampaignResponse` |
| `cancel(campaign_id, idempotency_key=None)` | POST `/{campaign_id}:cancel`, no body | `CampaignResponse` |

Create/action keys become `Idempotency-Key`; update requires `If-Match`. Writes never automatically retry. Pagination uses `iter_pages` / `iter_all`, default 50, limits 1–200, order `create_ts.desc` or `create_ts.asc`. Status is one of scheduled/running/paused/completed/canceled/failed.

Contacts contain E.164 `phone` and optional primitive `values` (≤100 keys), 1–50,000 contacts per campaign, with a 10 MiB create-body limit. Transport uses `type="telephony"`, `from` project number UUID or UUID list, optional call policy. Schedule is immediate or scheduled (IANA timezone and local `YYYY-MM-DDTHH:MM` start/end). Pacing supports `max_concurrent` and `calls_per_second`; removed retry fields are rejected. No SDK retry algorithm is implemented.

After calls begin, only pacing changes are supported; schedule, lifecycle and call-policy changes return `409 CampaignNotEditable`. Pacing merges; schedule and call policy replace (`{}` clears policy). Pause/cancel/end time stop new calls but leave active calls running. Invalid actions return `409 CampaignInvalidState`; deleting active campaigns returns `409 CampaignActive`. Contact results/events/webhooks are deferred, and campaign/session association is still planned. No unsupported endpoints are synthesized.

### Corrected release contract

Campaign create accepts 1–50,000 contacts and at most 10 MiB of JSON. `data_policy` is create-only and defaults to `30_days`; pacing contains only `max_concurrent` (1–10,000, request default 10) and optional `calls_per_second` (1–1,000). Removed retry fields are rejected. These schema ranges are not operational project quotas. Campaign silence has a 30,000 ms minimum; lifecycle limits extend to 259,200,000 ms. Session lifecycle limits remain 3,600,000 ms.

Session PATCH accepts `transport={"token": "..."}` and/or `agent={"overrides": {"messages": [...], "pipeline": {"llm": {"params": {...}}}}}`; use `mllm` instead of `llm` for realtime. Do not send both modules. Params replace the complete active module params; endpoint aliases, credentials, vendor and other configuration are not mutable. No ETag is required. AgentKit `session.update({"token": "...", "messages": [...], "llm": {"params": {...}}})` maps to this shape; `llm.system_messages` remains a compatibility spelling for messages. The existing legacy update path remains unchanged.

Session start/ephemeral and campaign create/pause/resume/cancel accept optional 1–256 visible ASCII `Idempotency-Key` values. Replays are retained for 24 hours and may return `Idempotent-Replayed: true`; conflicting/in-flight reuse returns `409 IdempotencyKeyConflict`. No automatic write retry occurs.
